# שמירה על רספונסיביות

כלל ברזל: **מסך שלא נבדק בשלושה רוחבים אינו גמור.** הסקיל משלים את `design-routing` (שקובע מי מכריע בהחלטה עיצובית) ונשען על כללי הנגישות של `ui-ux-pro-max`.

## רוחבי עבודה (נעולים; חריגה רק בהחלטה מתועדת)
| פריים | רוחב | שימוש |
| --- | --- | --- |
| Mobile | 390 | ברירת המחדל לתכנון; נבדק גם ב־360 |
| Tablet | 768 | |
| Desktop | 1280 | תוכן ראשי בעמודה עד 1040 במרכז |

שם הפריים: `<מסך> / Mobile 390`, `<מסך> / Tablet 768`, `<מסך> / Desktop 1280`. בכל מסך חדשים שלושתם.

## כללים ל־Figma
1. **Auto Layout בלבד** למכלים עם ילדים קשורים. אין מיקום ידני (x/y) בתוך מסך, חוץ מקישוט שסומן `ABSOLUTE`.
2. **רוחב ילדים `FILL`, גובה `HUG`.** אין רוחב קבוע לטקסט או לכרטיס. רוחב קבוע רק לפריים הראשי ולעמודת תוכן עם מקסימום (למשל 1040).
3. **שורות שעלולות לגלוש** (צ׳יפים, תגיות) הן `layoutWrap = WRAP`, לא שורה שנחתכת.
4. **מטרות לחיצה לפחות 44×44**; ריווח בין מטרות לפחות 8.
5. **RTL:** סדר ילדים בשורה הפוך (הראשון הלוגי מימין). כיוון הנגישות והקריאה נבדק בצילום, לא מניחים.
6. **מה קורה בכל רוחב** נכתב לפני העיצוב, בשורה לכל רכיב: מה מתקפל, מה נעלם, מה עובר לגיליון. דוגמה: סרגל מסננים בדסקטופ ← גיליון ״סינון״ בטלפון.
7. **אין גלילה אופקית** בפריים. תוכן רחב (טבלה) מקבל מקטע גלילה מוגדר.
8. **גודל טקסט גוף לפחות 16px** בטלפון.

## בדיקה (חובה לפני סיום)
- צילום של כל אחד משלושת הפריימים. לחפש: טקסט חתוך, חפיפות, גלישה, מטרות קטנות, כותרת שנשברת ליותר משתי שורות.
- אחרי שינוי ברכיב: לבדוק את כל המסכים שמשתמשים בו.

## כללים לקוד (כשנגיע לשלב הקוד)
- Mobile-first; נקודות שבירה לפי תוכן. רכיבים עם `container queries`.
- טיפוגרפיה זורמת עם `clamp()`; גובה מסך עם `dvh` ולא `100vh`.
- שדות קלט בגודל 16px לפחות (למנוע זום אוטומטי ב־iOS).
- מאפיינים לוגיים (`margin-inline`, `padding-inline`) ולא שמאל/ימין, בגלל RTL.
- בדיקות בצילום ב־360, 390, 768, 1024, 1440.
