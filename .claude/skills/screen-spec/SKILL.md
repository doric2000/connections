# אפיון מסך

מבוסס על שלב 2 בתוכנית הבנייה וכלל הסיום של מסלול העבודה. תוצר: סעיף קצר (טבלאות ורשימות), בעברית, שמצורף ל־`docs/screens/<שם>.he.md` או לסעיף המתאים ב־brief.

## מבנה
1. **מטרה ומשתמש** — מי המסך משרת ולאיזו משימה (משפט אחד).
2. **תוכן** — טבלה: רכיב · מקור (פרופיל/פנייה/אוטומטי) · חובה/לבחירה · סטטוס (`אושר`/`מוצע`).
3. **פעולות** — לכל פעולה: מי מבצע · מה רואה לפני · מה קורה אחרי (מצב חדש, התראה לצד השני, מה נשמר).
4. **מצבים** — ריק, טעינה, שגיאה, אין הרשאה, פנייה כפולה, נמשכה, פרויקט/תפקיד סגור לגיוס, משתמש חסום.
5. **הרשאות** — אורח / משתמש / פונה / בעל פרויקט / משתתף שיחה / חבר צוות / מנהל: מי רואה מה (ציבורי מול פרטי).
6. **RTL וטלפון** — הערות רלוונטיות בלבד.
7. **שאלות פתוחות** — רק מה שחוסם את המסך.

## כללים
- השתמש במצבים ובמונחים מ־`docs/glossary.he.md`. אל תמציא מצב חדש בלי לסמן `מוצע`.
- אל תוסיף מילוי חובה למועמד שלא אושר.
- לא לתכנן UI ויזואלי, צבעים או קוד; זה שלב האפיון.
- אל תחזור על החלטות — הפנה אליהן.
